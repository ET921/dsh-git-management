- `docs/reviews/product.md` — 產品設計工程師（功能取捨）

- `docs/reviews/gitexpert.md` — Git/GitHub 底層專家（正確性與邊界）

你寫的是其中一份。現在讀**其他四份**，然後在你自己的文件**末尾追加**一個 `## 交叉評審回應` 區段。

## 追加內容的格式

1. **同意並借用**：別人提的哪些點你認同、願意併入你的推薦（註明出處，例如「同意 gitexpert 的 pathspec 萬用字元污染，這在我的清單裡漏了」）。
2. **不同意**：哪些點你反對，寫出理由（技術、產品或體驗層面），不要客氣但要講道理。
3. **修正自己**：看完別人的，你的原發現有哪些要撤回、降級或加強？
4. **最終 Top 3**：綜合所有人的意見後，從**你的角色視角**認為整個專案最該做的三件事，各一句話說明為什麼。

## 硬性規定

- 只能修改**你自己負責的那一份**文件（末尾追加，不改第一輪的內容，最多微調明顯事實錯誤），不得動別人的檔案、不得動 `src/`、`scripts/`、`lib/`、`README.md`。
- 不執行 `npm install`、不 commit、不 push、不跑 `npm test`。
- 追加區段控制在 60 行內：重點是判斷與取捨，不是複述。回應要點名（誰的哪一條），不寫「大家說得都很好」。
- 最後一個動作必須是確認自己的文件已更新（列出檔案行數）。
