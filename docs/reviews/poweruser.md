# 重使用者評審：DSH Git 面板（poweruser）

角色：VS Code Source Control／Cursor Git 介面十年重度使用者，每天暫存、提交、看差異、切分支幾十次。
方法：唯讀，以「用讀的把面板操作一遍」完成（未跑程式、未改任何檔）。引用格式 `檔:行`；優先級 P0＝每次都卡、P1＝常用、P2＝偶爾。

## 二、摩擦點（每項：場景 → VS Code → 這裡 → 建議）

**F1 差異頁沒有暫存／放棄鈕，review 回圈斷裂（P0）**
- 場景：早上逐個 review 6 個變更，看完一檔想按 `+` 繼續，卻發現差異把整欄吃掉了。
- VS Code：清單常駐側欄、diff 在編輯器，「看一個 → 按 + → 看下一個」手不停；↑/↓ 走檔也一樣順。
- 這裡：`45-diff-panel.js:154-211` 的 header 只有返回、badge、`↑↓`、全文／並排、關閉，**零動作鈕**；回清單要再點一次 tab。
- 建議：header 的「已暫存／未暫存」badge 旁加兩顆 22px 鈕——`+`（暫存／取消暫存，依 `target.staged` 切）與 `↩`（放棄，沿用 `discardConfirm` 確認）。`↑↓` 換檔後直接按 `+`，回圈補完。

**F2 錯誤／成功提示在捲軸最上方，捲到下面就看不見（P0）**
- 場景：檔案清單在畫面下方，按「放棄」失敗（Windows 上檔案唯讀），畫面紋風不動，我以為鈕壞了——紅字其實在最上面，`gmg-root` 是捲動容器（`30-style.js:14-16`），根本沒在視窗裡。
- VS Code：通知是浮動 toast＋Output 面板，永遠在視線內。
- 這裡：`.gmg-notice` 是 `gmg-page` 頂端的普通區塊（`40-panel.js:125-155`），頁面一捲動就出畫面。
- 建議：notice 改 `position: sticky; top: 0; z-index` 疊在捲動容器頂端（一行 CSS），或改浮動 toast（3 秒自動消失，error 停留）。錯誤必須出現在「我剛按的那顆鈕」附近。

**F3 節奏：每次檔案動作全量重讀＋busy 鎖法不一致（P1）**
- 場景：5 個檔案要逐個暫存，每按一次 `+` 就重跑 status（含 2 次 numstat）＋`log -n40`＋`for-each-ref`（`10-store.js:153-167`、`270-276`），期間分支列／刷新鈕全灰；更糟的是檔案列的 `+`／`↩` **完全沒有 disabled**，與 8 秒輪詢併發時兩個 `task()` 互相覆蓋 `busy`（`10-store.js:94-104`），先完成的把旗標清成 null，UI 顯示閒置但 git 還在動。
- VS Code：樂觀更新＋增量刷新，動作當下就移動列，背景再對帳。
- 這裡：樂觀更新沒有，鎖卻鎖錯對象。
- 建議：① stage/unstage 先樂觀把該列搬到另一組再背景重讀；② 檔案動作只重讀 `status`，`log`/`branches` 留給 commit/pull/push；③ 輪詢的 `busy='refresh'` 不要禁用分支列鈕（只轉自己的刷新圖示）；④ 檔案列鈕補 `disabled: busy !== null`，或改用單一 in-flight guard。

**F4 amend 沒有預覽、沒有確認，stageAll 還不會自動取消（P1）**
- 場景：想修上一筆的錯字，勾「修改上次提交」，輸入框是空的，只打了 `fix typo` → `git commit --amend -m` 把原本三行的完整訊息**整段換掉**（`10-store.js:301-305`）；隔天又發現 `stageAll` 勾選跨提交留存（commit 只清 `amend`、不清 `stageAll`），默默 `add -A` 把剛放進資料夾的憑證一起提交。
- VS Code／GitHub Desktop：amend 會把上一筆訊息放回輸入框讓你改，且是「這次才生效」的選項。
- 這裡：常駐 checkbox＋無 sha／無原訊息提示。
- 建議：勾 amend 時抓 `commitDetail`，在輸入框上方放一行「將改寫 `abc1234 · 原主旨`」，並把原訊息填進輸入框（不覆蓋已打的字）；commit 成功後連 `stageAll` 一起重設；amend 與 stageAll 同時勾時加一次確認。

**F5 分歧時 pull 必失敗，沒有出路（P1）**
- 場景：本地 3 個 commit、遠端也前進，按「拉取」→ 紅字 `Not possible to fast-forward`，面板沒有下一步，只能開終端。
- VS Code：命令面板有 `Pull (rebase)`／merge，狀態列也有入口。
- 這裡：`git.js:476-479` 寫死 `--ff-only`，hint 只是 tooltip 文字。
- 建議：`ahead>0 && behind>0` 時 pull 鈕右側出一個小 chevron（fast-forward／`--rebase`／merge 三項）；至少在錯誤列下附一行「或執行 `git pull --rebase`」＋複製鈕。

**F6 分支選單沒有搜尋、沒有遠端分支、建立入口在外面（P1）**
- 場景：40 個分支只有上下鍵，滾到眼花；想切一個只在 `origin` 的分支，選單裡根本沒有。
- VS Code：分支選單頂端有輸入框即時過濾、列遠端分支、含「建立分支」入口。
- 這裡：`40-panel.js:642-690` 只列 `refs/heads`（`git.js:437`），無輸入框；「新建分支」的表單反而掛在 pill 旁的 `+`（`40-panel.js:744-788`），窄欄會擠成兩列。
- 建議：選單頂端加過濾框（打字即過濾、Enter 選第一項）、遠端分支列為次區塊（選了走 `switch -c x --track origin/x`）、「建立分支」搬進選單底部。

**F7 衝突列零按鈕，解完沒法從面板暫存（P1）**
- 場景：pull 產生 2 個衝突，在編輯器解完回來，「衝突」列只剩檔名——`FileRow` 在 `conflicts` 時不渲染任何 action（`40-panel.js:949` 的 `else if (!conflicts)`），點開 diff 也只看到 marker，最後還是開終端 `git add`。
- VS Code：衝突檔解完後可直接 stage。
- 這裡：連 `+` 都沒有（README 聲明不做衝突解決器——同意，但「解完後暫存」不是解決器）。
- 建議：衝突列給一顆 `+`（`git add`）與一行灰字提示「編輯完成後按 + 暫存」；其餘 ours/theirs 進階動作可繼續不做。

**F8 Fetch 在沒有上游時被禁用＋重新整理時機是黑箱（P1）**
- 場景：剛建的本地分支（還沒 push），想看 origin 有沒有新東西 →「獲取」是灰的（`40-panel.js:727` `upstream === null`）；另外終端機 commit 完切回分頁，不知道面板什麼時候會跟上，只能盯著等。
- VS Code：fetch 永遠可用；視圖可見即刷新，狀態列顯示同步狀態。
- 這裡：fetch 被上游條件擋死；輪詢 8 秒＋focus 才刷（`40-panel.js:44-57`），無「上次更新」提示，重新掛載後第一次 tick 還要等滿 8 秒。
- 建議：fetch 只看 `busy`；掛載時若已有 path 立刻 `refresh()`；刷新鈕旁加一個「X 秒前」小字（或 busy 時才轉）。

**F9 歷史列點不開，hover 卡沒有任何可點元素（P1）**
- 場景：想知道 `abc1234` 動了哪些檔，把滑鼠停上去只看到主旨＋統計——想開 GitHub、想複製 sha，卡上一個連結都沒有；README 第 45 行寫的「在 GitHub 開啟」在 `46-hover.js:296-321` 不存在（文件與程式碼已脫節）。
- VS Code／GitLens：點提交開出檔案清單／diff，卡上可點。
- 這裡：列不可點（`40-panel.js:299-316`），資料其實已經有了（`commitDetail` 回 `files`）。
- 建議：點列原地展開該提交的檔案清單（每項開 diff）；hover 卡尾加「在 GitHub 開啟」連結＋複製 sha 鈕。

**F10 錯誤只剩第一行、成功提示永不消失（P2）**
- 場景：push 被拒只有一行 `Updates were rejected…`，分不清是非快進還是權限；另一天綠色「已放弃更改」掛了十分鐘沒清（`task()` 只清 error 不清 notice）。
- 這裡：`error.details`（argv/stderr）在 `00-util.js:138` 有拿到，卻在 `10-store.js:99` 被丟掉。
- 建議：錯誤列加「詳情」展開顯示 `git …` 與 stderr 尾段；已知模式（non-ff、髒檔擋 checkout）補一行中文下一步；成功 notice 3–5 秒自動淡出。

**F11 差異預設全文、並排在 360px 截斷（P2）**
- 場景：開一個 900 行的檔，diff 顯示全文，得先找「僅變更」；切「並排」後左右各約 150px，`overflow: hidden`（`30-style.js:356`）直接把長行切掉，看不出改了什麼。
- VS Code：預設 3 context；編輯器夠寬才會用並排。
- 這裡：`context: 'full'` 為預設（`15-diff.js:29`），並排鈕在窄欄照常可用。
- 建議：`is-compact` 時預設 `hunks`；欄寬 < 400px 時隱藏或禁用「並排」鈕。

**F12 檔案列沒有右鍵選單（P2）**
- 場景：要複製路徑、想「開啟檔案」而不是開 diff，只能滑鼠懸停找那兩顆 22px 鈕。
- VS Code：右鍵一整包（Open File／Open Changes／Copy Path／Stage Selected Ranges…）。
- 這裡：`40-panel.js:984-1014` 無 `onContextMenu`。
- 建議：context menu 至少四項：複製路徑、複製 diff、在 GitHub 開啟、開啟檔案（走 DSH 檔案面板）。

## 三、習慣有、這裡沒有：值不值得塞進 ~360px

| 習慣 | 值不值得 | 放哪／長相 | 優先級 |
| --- | --- | --- | --- |
| 全部放棄（discard all） | **值得** | 「更改」組標題右側一顆 `↩`（與 `+` 對稱），確認框列出檔數 | P1 |
| hunk 級暫存（`@@` 列上的 `+`／`↩`） | **值得** | diff 的 hunk header 已是整列，加兩顆鈕即可，無需改資料流以外的東西 | P1 |
| line 級「選取行暫存」 | 不值得 | 360px 選取易誤觸，且要引入選取狀態機 | P2 |
| stash | **值得**（低頻但關鍵） | 分支列尾的「⋯」內一項：切分支被髒檔擋住時唯一出路 | P1 |
| 撤銷上次提交（限未推送） | **值得** | 歷史組標題「⋯」，帶確認 | P2 |
| 設定上游／checkout 遠端分支 | **值得** | 併入 F6 的分支選單 | P1 |
| pull 的 rebase 選項 | **值得** | 見 F5 | P1 |
| 點提交看檔案 | **值得** | 見 F9 | P1 |
| 複製 sha／路徑 | **值得** | hover 卡與右鍵選單 | P2 |
| 開啟檔案（非 diff） | 半值得 | 右鍵一項即可 | P2 |
| 變更清單過濾框 | 半值得 | 變更 > 30 個才出現 | P2 |
| 多倉庫縱向堆疊 | **不值得** | 360px 會變成 N 倍捲動；現有下拉是對的 | — |
| 拖曳檔案跨組暫存 | **不值得** | 目標只有 1 列高，誤放成本大於節省 | — |

## 四、最痛的三件事

1. **F1 差異頁不能暫存**：每天 review 都要多繞一圈返回，這是與肌肉記憶落差最大的一處。
2. **F2 提示看不見＋F3 忙碌鎖錯對象**：合起來就是「我按了，面板沒反應」——重使用者對這種沉默的容忍度是零。
3. **F4 amend**：低頻但代價最高，靜默改寫歷史，事後只能翻 reflog。

## 五、學了反而壞事的 VS Code 設計

1. **把 diff 開在中欄編輯器**：VS Code 靠這招讓清單常駐，但在 DSH 會吃掉對話欄。同欄新 tab 是對的，別照搬——補上 F1 的差異頁動作鈕就補完了迴圈。
2. **「⋯」三、四十項選單＋命令面板逃生艙**：窄欄裡常用動作藏進選單＝每次多一層。這裡只該收低頻（stash、撤銷提交、prune），常用必須露在外面。
3. **smart commit（沒暫存就自動 `add -A`）**：會把剛丟進資料夾的憑證、大檔、node_modules 一起提交。這裡 `stageAll` 是明示勾選，別把它變成預設或自動。
4. **多倉庫縱向堆疊**：VS Code 在寬螢幕很好用，360px 會變成無止盡捲動；下拉切換是正確取捨。

## 交叉評審回應

### 同意並借用

1. **gitexpert §一 pathspec 萬用字元污染（P0）**：我的清單整個漏掉，而它打的正是我每天按幾十次的逐檔 stage/discard——`b[br]acket.txt` 會誤命令到別的檔，屬資料層誤操作，直接併入我的 P0。
2. **gitexpert §二 衝突 diff 的 `--cc` 未處理＋product G2**：我的 F7 只寫「解完沒法暫存」，其實點開看到的 diff 本身就是錯字錯行號；F7 從「少一顆鈕」升級為「衝突流程兩端都斷」。
3. **engineer 發現 3（busy 為可覆蓋單一標籤、8 秒輪詢清 error）**：這是我 F3「鎖錯對象」的完整病理，採納其 busy token／errorSeq 方案，取代我原本「檔案列補 disabled」的半套修法。
4. **engineer 次要項 `selectRepo` 不重設 diff store**：正是 F1 `↑↓` 迴圈的邊界——切 repo 後舊檔清單還能按，併入 F1 驗收條件。
5. **product G1/G2＝我的 F5/F7，G4/G9＝我的 §三**：借 product 的「已分歧」狀態標籤與 stash 數量徽章；撤銷提交由我升級 P1（見下）。
6. **design `:focus-visible` 缺失（P0）**：我的核對表只測滑鼠；分支選單可鍵盤操作、檔案列 Tab 過去看不見焦點，是同一套肌肉記憶的另一半，併入清單。

### 不同意

1. **design「hover 卡不可點、不要加連結」（§不建議動）**：F9 要的是「在 GitHub 開啟」與複製 sha，屬外開與剪貼簿，不與列點擊競爭；「唯讀」不等於「不可導航」，GitLens 的 hover 卡也是連結優先。
2. **design 把 `.gmg-actions` hover 才顯列為 P1 要調亮（§變更清單）**：與其自身「不建議動」章節互相矛盾，且與 VS Code 同款——hover 才顯正是 360px 的正確密度解，我維持現狀。
3. **product §五把「更頻繁刷新」與 F8 捆綁打掉**：我從未要求 fs.watch；F8 要的是「X 秒前」可見性與掛載即刷，engineer 也反對提頻率——反對的是成本，不是把同步狀態變黑箱，兩者別綁一起。

### 修正自己

- **升級**：F7（併 gitexpert `--cc` 與 product G2）；§三「撤銷上次提交」P2→P1；F5 對齊 product 標 P0（agent 常推遠端的環境裡分歧是常態）。
- **降級**：F3 建議④「`disabled: busy !== null`」降為附帶——busy 結構不改，disabled 只會把錯誤一起鎖死（engineer #3）；F11 維持 P2，design 已證實單欄橫向捲動正確，只需修並排截斷。
- **加強**：F2 修法收斂為 sticky notice 先行（一行 CSS）、toast 二期；F4 加上 stageAll 跨提交留存後，定調為「靜默改寫歷史＋靜默擴大提交範圍」雙雷。

### 最終 Top 3（poweruser 視角）

1. **F1 差異頁補暫存／放棄（含 hunk 級、selectRepo 重設）**：每天幾十次的 review 迴圈斷點，與肌肉記憶落差最大的一處。
2. **F2＋F3＋engineer #3 的提示可見性與 busy/error 生命週期**：重使用者對「我按了、面板沒反應」的容忍度是零，其他功能補不回這個信任。
3. **衝突收尾鏈（F7＋`--cc` 降級＋product G2/G3 標記已解決）**：目前唯一「看得到卻完全做不下去」的流程，兩端修完才談得上不開終端。
